# Context

Context explains what an engineering agent needs to understand before changing the system. Load it progressively: start from the relevant workspace manifest, then follow links to architecture, product, strategy or engineering-process context only when the task requires them.

Context is descriptive. Constraints live in `../rules/`, required behavior in `../specs/`, and decision history in `../adrs/`.
