# Local voice and Memory MVP

SPEC-050 → SPEC-051 → SPEC-052 implements the owner's first-option decision: OpenAI Realtime handles speech-to-speech and interruption; LangGraph orchestrates background Memory. WorkOS integration is deferred for this loopback-only, single-owner profile. Follow [startup](../../../../workspaces/packages/runtime/mvp.md); provider secrets stay in the central ignored environment, never in browser configuration.

Audio travels directly between the browser and OpenAI over WebRTC. Chatterbox establishes the session and runs a parallel control/Memory sideband; it is not an audio relay and does not add an HTTP round trip to every spoken turn. The owner plans an Orbs connection-adapter prop. The current wrapper exposes visual state; its future adapter should use an authorized session factory and public model configuration, never the permanent provider key.

The PWA obtains an expiring server conversation and explicitly confirms Memory consent before microphone capture. Chatterbox creates the provider call and binds a server sideband to that conversation and subject. Only finalized provider input transcriptions enter the governed buffer with `realtime-transcript` provenance. Browser transcripts, Ana output, provisional text and inactivity are not evidence. No raw audio is stored by this bridge.

Neo4j owns consent, evidence, outbox, claims, activation and suppression. One reference-only BullMQ queue runs on persistent Redis Queue; Redis Cache is a physically separate instance. The compiled LangGraph has deterministic claim/admission, curation, completion and release branches, reusing the existing curation use case and provider attempt accounting. Graph state contains bounded outcomes; protected execution stays in invocation closures. No graph checkpoint database or extra answer model is added.

The Realtime `memory_search` tool uses the public Memory SDK, a 600-token retrieval budget and current consent. Tool output is untrusted data. Buffered or queued evidence does not imply accepted Memory; the UI reports accepted records only when governed recall returns them. An internal allowlist enables owner curation; Free background remains off. Existing shadow/canary admission evidence is not a prerequisite to this explicitly selected local bridge, and those experiments are not activated by the launcher.

The provider's VAD enables interruption. PWA stop closes microphone, audio and peer; Chatterbox fences and hangs up the server call. Ownership, expiry, bounded pending events and heartbeat cleanup limit abandoned sessions. These lifecycle paths are implemented but have not been exercised against live providers.

Models are server-configurable. Response completion records reported audio/text/cached usage, including cancelled responses when reported. Prices, speech durations and separate input-transcription billing that are not observed remain unknown. Crash or shutdown may lose final accounting. This implementation does not prove minimum cost, naturalness, complete cost reconciliation or plan margins. SPEC-049 retains those measurements, browser/provider scenarios and migration of historical calendar-demo evals. SPEC-033/034 retain broader application guardrails and multi-user lifecycle work before external exposure.
